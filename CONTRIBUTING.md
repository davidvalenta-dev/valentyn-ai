# Contributing to Valentyn

Each research change should state a falsifiable hypothesis, a strong baseline, a fixed evaluation budget, and the outcome, including negative results. Prefer a small experiment that isolates a mechanism over adding several interacting engines.

Run `sh scripts/setup.sh`, activate `.venv`, and run `sh scripts/check.sh`. Include a reproducible command and machine-readable results for algorithmic changes. Regenerate reported evidence after changes to code, corpus, or toolchain. Keep local databases and virtual environments out of Git.

Do not select policies, tune hyperparameters, or invent curricula from final test results. New theorem families require canonical structural deduplication and an explicit statement of what kinds of equivalence remain unchecked. Success on the public development suite does not establish contamination-free generalization.

Proof-generating components propose; Lean accepts. Never bypass rejected proofs, remove the axiom audit to obtain a positive result, count a timeout as disproof, or label a finite numerical check as a universal theorem. Explain whether a formal theorem matches the intended informal problem.

Candidate source code must not run on the host under the name of a sandbox. The existing worker is for validated policy data only. Any future source-evolution contribution needs a documented OS-level isolation design, immutable evaluation assets, resource and network controls, and adversarial checks.

Claims of mathematical novelty need prior-art checks and independent mathematical review. Claims of recursive improvement need held-out gains after all search/training/selection costs. Preserve failed experiments that changed a research decision.
